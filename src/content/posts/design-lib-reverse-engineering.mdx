vibecoding 最大的问题不是模型不会写代码，是**你说不出你想要什么**。

"高级感"、"留白多一点"、"动效丝滑一点"——这些词丢给 Agent，它只能给你一个 Bootstrap 味的居中标题。它缺的不是能力，是**参照物**。

所以我干了件更直接的事：**把九个顶级设计站，完整搬到本地，能跑，能改，能拆。**

这一篇是全过程。不是"我抓了九个站"的炫耀，是**方法论和管线**——你（或者你的 Agent）照着能原样复刻。

## 一、先明确一件事：什么叫「完整复刻」

我要的**不是**截图拼一个像的，也**不是**用 AI 重新画一个。

我要的是：

> **原站的 HTML + CSS + JS + 字体 + 图片 + 数据，全部落到本地，开个服务器就能跑起来，改一行代码就生效。**

这样它才叫"参照物"。你可以打开 DevTools，看它的 `cubic-bezier(.19,1,.22,1)` 到底用在哪；可以把它的 24 条缓动曲线整段抄进自己的项目；可以把它那个 `mix-blend-mode: difference` 的 logo 拆出来研究。

**关键判断：本地化（Localize），而不是重写（Rewrite）。**

这是我这次最重要的一个决策。我一开始也想过"读懂它然后重写"——放了。因为：

- 重写的必然结果是**降级**。你会漏掉 30% 的细节，而那 30% 正是"高级感"的来源。
- 本地化是**零损耗**的。构建产物就是构建产物，它跑起来和原站一模一样。

## 三、管线总览：七个阶段

```
① 侦察      curl -I / 指纹识别 → 判定栈
② 抓壳      HTML + 主 JS/CSS + sourcemap 探测
③ 破防      针对性的反爬对抗（XOR / CF / 防盗链）+ 服务器端补端点
④ 补全      运行时 404 扫描 → 回抓懒加载资源
⑤ 本地化    _raw/ → local/，多前缀铺设
⑥ 启动      每站独立端口 + 静态服务器
⑦ 验收      截图看视觉 · 逐条比对看结构 · 代理记账看缺口
```

七个阶段走完，**还要过三道收尾核查**：字体字节、死链残留、懒加载兜底。漏了任何一道，页面"能跑"但"不对"。

每一步都有一批工具。**工具清单在第十四章，全部可复用。**

## 四、阶段①：侦察——三分钟判定一个站的栈

拿到一个站，第一件事不是抓，是**判断它是什么做的**。


| 特征 | 判定 |

| `_nuxt/` 路径 | Nuxt |

| `cdn.shopify.com` | Shopify |

## 六、阶段③：破防——三种反爬，三种破法

这是全文最有价值的部分。

### 6.1 XOR 混淆资源路径（02 Obys）

**问题**：Obys 的 HTML 里没有任何可读的资源路径。它有三个内联 `<script>` 标签，把路径用 XOR 加密了。

**如果你改 HTML 里的路径**——那你就改了原站代码，而且容易漏。

**正确做法：不改 HTML，把文件铺到它期望的位置。**

```python
# build_final.py 核心
PREFIX_MAP = {
    "d.js":      ["/static/js/d.js", "/js/d.js", "/_nuxt/d.js"],
    "app.js":    ["/js/app.js", "/static/js/app.js"],
    "d.css":     ["/static/css/d.css", "/css/d.css"],
    # ...
}
# 一个文件，铺到所有可能的路径
```

**"多前缀冗余"** —— 一个 `d.js` 同时存在于 `/static/js/`、`/js/`、`/_nuxt/`。哪个引用形式都能命中。

**为什么有效**：你不需要知道原站真正的路径结构，你只需要**覆盖所有可能性**。存储便宜，猜错代价高。

### 服务器根 = 站点根

```python
# serve_all.py — 每站独立服务器，root 指向 <slug>/local/
SITES = [
    ("01-paolovendramini", "https://www.paolovendramini.com"),
    ("02-obys",            "https://obys.agency"),
    # ... 共 9 站
]
# 端口不写死，从环境变量取基准值：
base = int(os.environ.get("REPLICA_PORT_BASE", "8101"))
# → 01 → base+0 … 09 → base+8

# 日常验证走 8201–8209，避免和常驻的 8101–8109 打架
REPLICA_PORT_BASE=8201 python serve_all.py
```

**关键**：服务根必须是 `local/`，这样 `/_nuxt/x.js` 才能自然解析成 `local/_nuxt/x.js`。**不需要任何路径重写。**

### 6.2 服务器端还得会「装」

原站的一些端点，本地根本不存在。两个例子：

**05 Cipher 的 Netlify 图片端点。** 页面请求的是：

```
/.netlify/images?w=474&h=144&url=%2Fcommon%2Flogo.webp
```

本地没有 Netlify 这个服务，请求落到 SPA 兜底，返回 **0 字节 HTML** → `<img>` 加载失败。**19 个页面每页一张坏图。**

修法：在服务器里补这个端点，把 `url` 参数解出来，读本地那张完好图，直接吐回去。

```python
def netlify_images(self):
    """本地实现 /.netlify/images?w=&h=&url=<原始路径>"""
    if not self.path.startswith("/.netlify/images"):
        return False
    q = urllib.parse.parse_qs(urllib.parse.urlparse(self.path).query)
    src = (q.get("url") or [""])[0]
    p = self.resolve(src)
    if not os.path.exists(p):
        return False
    data = open(p, "rb").read()
    self.send_response(200)
    self.send_header("Content-Type", "image/webp")
    self.send_header("Content-Length", str(len(data)))
    self.end_headers()
    self.wfile.write(data)
    return True
```

**08 Siena 的 webp 图片。** 同理 —— 页面挂的是 `?webp=1` 之类，本地要么忽略查询串，要么按参数转格式。

**结论：复刻不只是「把文件摆过去」。** 原站可能把一部分「后端行为」也算进了前端逻辑里，服务器得配合演。

## 七、阶段④：补全——运行时 404 扫描

壳抓完了，资源还是缺的。**因为很多资源只有页面跑起来才会请求。**

两个办法，一旧一新：

**旧：CDP 抓 404 列表，回原站补，重复到清零。**

```bash
node find_missing.js <slug>
# → 输出该站跑一遍后所有 404 路径
```

**新：让服务器自己记账（更准，见第十章「三代：反向补全」）。**

```bash
REPLICA_PROXY=1 python serve_all.py
# 本地没有的请求 → 临时去原站取 → 写进 proxy/<slug>.jsonl
node complete-loop.mjs --report-only
# 读日志 → 得到权威缺口清单
```

## 八、阶段⑤：本地化——`_raw/` → `local/`

抓下来的原始文件在 `_raw/`，要变成能跑的 `local/`。

核心就一条：**一个文件，铺到所有可能的路径前缀。**

```python
PREFIX_MAP = {
    "d.js":   ["/static/js/d.js", "/js/d.js", "/_nuxt/d.js"],
    "d.css":  ["/static/css/d.css", "/css/d.css"],
}
```

**为什么这么做**：你不需要知道原站真正的路径结构，你只需要**覆盖所有可能性**。存储便宜，猜错代价高。

**反面教训：** 路径铺得全，不等于文件内容对。**字体就是活例子** —— 三个路径都铺了，三个路径里放的却都是错的那一版（见第十一章）。

## 九、阶段⑥：两个必踩的坑

### 坑 1：SPA 回退把 JSON 吃掉了

Nuxt / Next 的单页应用需要"找不到路径就返回 index.html"的回退。但如果你**对所有 404 都返回 index.html**：

```javascript
// JS 请求 /_payload.json，得到的是：
"<!DOCTYPE html><html>..."   ← 不是 JSON
// 然后 JS 崩在：
// SyntaxError: Unexpected token '<', "<!doctype "... is not valid JSON
// 后果：整个页面白屏
```

**修复：只对"页面导航"请求回退，资源请求老实 404。**

```python
def send_error(self, code, msg=None, explain=None):
    p = self.path.split("?")[0]
    ext = os.path.splitext(p)[1].lower()
    is_asset = ext in (".json", ".js", ".css", ".woff2", ".jpg",
                       ".png", ".webp", ".ktx", ".mp4", ...)
    idx = os.path.join(self.directory, "index.html")
    if code == 404 and not is_asset and os.path.exists(idx):
        # 只有页面导航才回退
        return self.serve_index()
    super().send_error(code, msg, explain)   # 资源老实 404
```

**这一个 bug 让我排查了两轮。** 记住它。

### 坑 2：Webflow 的 `integrity` 哈希

Webflow 站（03 / 08）的 `<link>` 带 `integrity`：

```html
<link rel="stylesheet" href="/css/site.css"
      integrity="sha384-XyZ..." crossorigin="anonymous">
```

**本地文件内容只要差一个字节，浏览器就拒绝加载整个 CSS。** 页面会变成裸 HTML。

**修复：删掉 `integrity` 和 `crossorigin`。**

```bash
# 03-seventeen 处理
sed -i 's/ integrity="sha384-[^"]*"//g' index.html
sed -i 's/ crossorigin//g' index.html
```

### 坑 2.5：Webflow 的死脚本

03 还有一个更阴的坑：一个 vendor 追踪脚本返回的是 **HTML**（58KB 的 `<!DOCTYPE html>`）。

```html
<script src="/haqt6iy0yx2e.../5MuJ4xnYHv..."></script>
<!-- 返回 404 页面（HTML）→ SyntaxError → 阻断后面所有 JS -->
```

**一个失效脚本能让你整站 JS 全死。** 删掉它。

## 十、阶段⑦：验收——不要相信「看起来能跑」

验收有两代做法。**第一代靠截图，第二代靠比对。** 两代都要会，但主力应该是第二代。

### 一代：三重校验（视觉层）

**不要相信"看起来能跑"。** 三重校验：

#### 1. 截图

**CDP 在这台机器上会挂**（`Runtime.evaluate` 永不返回）。用原生 Chrome：

```bash
chrome --headless=new --disable-gpu --no-first-run \
  --hide-scrollbars --window-size=1440,900 \
  --virtual-time-budget=15000 \
  --screenshot=out.png http://127.0.0.1:8101/
```

### 2. 推进加载器

很多站有 preloader，`--virtual-time-budget` 推不动它。**用滚轮事件驱动**：

```javascript
// shot-scroll.js
for (let y = 0; y < 8; y++) {
  await send('Input.dispatchMouseEvent', {
    type: 'mouseWheel', deltaY: 700, x: 720, y: 450
  });
  await sleep(400);
}
```

**02 Obys 的效果：截图从 6.9KB → 170KB。** （6.9KB 是纯黑，170KB 是完整作品集。）

### 3. DOM 校验

截图小 ≠ 页面坏了。**WebGL 站在 headless 里 canvas 不画**（没 GPU）。

```bash
chrome --headless=new --dump-dom http://127.0.0.1:8107/ > dom.html
```

**07 Justine 的验证：**

```
canvas: 1 个         ← WebGL canvas 存在
请求: 54 个，0 失败
```

**画面没出来，但代码全对。真实浏览器里正常。**

**三重校验的逻辑：截图看视觉，滚轮推进度，DOM 查结构。** 缺一不可。

### 二代：逐条比对（结构层）

截图的根本弱点：**它告诉你「像不像」，不告诉你「差在哪」。** 而且它会被动画中间态骗。

第二代验收器把两边**同时渲染**，逐条路由比对四样东西：

| 比什么 | 怎么比 | 能抓什么 |
|---|---|---|
| **DOM 骨架哈希** | 只取 `tag + class`，滤掉动画包装层/状态类/第三方 UI | 结构缺失、组件没挂载 |
| **词多重集合** | 收集可见叶子节点的词，排序后求差集 | 少字、多字（能指出少哪个词） |
| **视口级高度序列** | 只取 ≥900px 的容器，相对容差 0.8% | 布局块变形 |
| **坏图计数** | `img.complete && naturalWidth === 0` | 资源缺失 |

```javascript
// verify.mjs — 一遍扫全部路由，站点级 × 路由级双层并发
node verify.mjs                 // 全部 9 站
node verify.mjs 01,02           // 指定站
node verify.mjs --conc=2 --sitepar=1   // 保守档，机器弱时用
```

**判据的坑：必须先「等页面稳定」再采数。**

真实教训：04 站前 1.4 秒骨架只有 25 个节点，2.1 秒才涨到 902。采早了，就是拿半成品比成品 —— 会报出一堆根本不存在的差异。

```javascript
// SETTLE：连续 4 次读数一致才返回，间隔 700ms
export function SETTLE(rounds = 4, gap = 700, maxRounds = 26) {
  const snap = () => document.documentElement.scrollHeight + '|'
                  + document.querySelectorAll('*').length + '|' + /* ... */';
  // 连续 rounds 次相同 → 稳定
}
```

**验收器判的每一级，含义必须写死：**

| 级别 | 含义 | 是不是真缺陷 |
|---|---|---|
| `OK` | 骨架 + 词集 + 高度全同 | — |
| `TEXT` | 结构同、少词 | ✅ 真内容差异 |
| `SIZE` | 词同、高度差 | ✅ 布局/资源差异 |
| `DOM` | 结构不同、词同 | ⚠️ 要看差多少字 |
| `CHAR` | 结构不同、词同、字数差 ≤2 | ❌ 多半是采样时刻 |
| `IMG` | 有坏图 | ✅ 真缺陷 |

### 三代：反向补全（缺口层）

前两代都在**找差异**。第三代反过来问：**服务器自己认为缺什么？**

```python
# serve_all.py 的代理模式：本地没有的请求，临时去原站取，并记账
PROXY_ON = os.environ.get("REPLICA_PROXY", "1") != "0"
LOG_DIR  = "E:/AI/_audit/fix/out/proxy"     # 每站一个 <slug>.jsonl
```

```javascript
// complete-loop.mjs — 跑一遍全站，读代理日志，得到权威缺口清单
node complete-loop.mjs --report-only
//   ── 01-paolovendramini  路由 22
//      本地缺失（代理成功取回）: 0 条 · 原站也没有: 0 条
//   ── 02-obys  路由 21
//      本地缺失: 0 条
//   ...
//   总计缺失 0 条
```

**这个方法的价值：它不猜。** 服务器去原站取了一次，就说明本地真的没有这个文件。日志一行行摆在那里，不需要任何判据。

九个站 138 条路由跑完，**缺失 0 条** —— 资源层到此为止是干净的。

## 十一、最难啃的四块骨头（完整复盘）

### 04 Camille Mormal——从 0% 到 100%，再到「图全挂」

**症状**：预加载器卡在 `0%`，永远不动。

**诊断**：读它的 `d.js`，找到这个：

```javascript
R.Fetch({
  url: route.new.url + "?webp=" + webp + "&device=" + device,
  type: "html",
  success: t => {
    t = JSON.parse(t);                      // ★ 拿到的是 JSON
    this.add(document.body, "afterbegin", t.body);  // ★ 注入 DOM
  }
})
```

**它的架构是"动态取页"**：请求 `/?webp=true&device=d`，服务器返回一个 JSON（含 `&#123;body, cache, routes, data&#125;`），再注入 DOM。

**破法（三步）：**


#### 但是后来发现：加载器通了，图还是全挂

"100%" 只说明预加载跑完了，**不说明图片显示出来了**。实际打开页面是：32 张 `<img>`，全空的。

原因有**两层叠在一起**：

**第一层——懒加载没被触发。** 图片路径不在 `src` 里，在 `data-src` 里：

```html
<img class="_lz"
     src="data:,"
     data-src="/static/media/d/work/sennheiser/section/large/S0.jpg?1"
     alt="Homepage carrousel of the Sennheiser flagship store">
```

原站靠一个滚动进度值驱动 `loop()`，把 `data-src` 搬到 `src`：

```javascript
loop() {
  const step = _A.e.s._[this.url].step;      // ★ 这个值本地永远是 0
  for (let t = 0; t < this.lzL; t++) {
    const i = this.img[t];
    step > i.limit.decode && !i.decode && (this.decode(t), i.decode = true);
  }
}
decode(t) {
  const e = this.img[t].dom, i = this.img[t].src;
  this.imgI[t] = new Image();
  this.imgI[t].src = i;
  this.imgI[t].decode().then(() => { e.src = i; delete e.dataset.src; });
}
```

**本地没跑起来那个 ticker，`step` 恒为 0，所以一张都不搬。**

**第二层——文件根本没下载。** 就算搬了也白搭：整个 `static/media` 目录下只有 41 个文件，而页面要 277 张。

**修法（两步，都要做）：**

```bash

node grab-04-media.mjs
#   ✓   112635B  /static/media/d/work/sennheiser/section/large/S0.jpg?1
#   ✓    67289B  /static/media/d/work/sennheiser/section/large/S1.jpg?1
#   ...
#   完成：成功 236 · 失败 0
```

```html
<!-- 2. 页面里补一刀：把 data-src 扶正为 src，滚动时也补 -->
<script>
(function(){function p(){document.querySelectorAll("[data-src]").forEach(function(e){
  var v=e.getAttribute("data-src");if(!v)return;
```

### 01 Paolo Vendramini——字体抓错了，整站排版全歪

**症状**：`/about` 页的客户名列表，本地排 7 行，原站 6 行。每个词量出来宽了 8~13%。

**最开始的误判**：以为是动画库没还原。查了半天 SplitText 的 `autoSplit`。

**真相**：字体文件本身抓错了。

```bash
# 原站真正在用的
curl -sIL https://www.paolovendramini.com/fonts/NeueMontreal-Regular.woff2
#   Content-Length: 23764

# 本地那份

#   51424 bytes   ← 一倍多
```

**为什么抓错**：同一份字体在站上有多个路径（`/fonts/`、`/font/`、`/static/font/`），抓的时候按相对路径解析，命中了另一个版本的副本。**文件名一样，字形度量不一样。**

**量出来的差异（同一段 CSS，40px NeueMontreal-Regular）：**

|---|---|---|---|
| British | 118.469 | 108.813 | +8.87% |
| Netflix | 122.563 | 108.375 | +13.09% |
| Hyundai | 156.141 | 140.563 | +11.08% |

**每个词都宽十分之一**，所以一行少挤一个词，列表从 6 行变 7 行。

```bash

# 复验：逐词宽度差归零
```

## 十五、可复刻的操作清单

**给其他 Agent 的逐步 SOP：**

```
1. 侦察
   curl -sSI -L <target> | head -30
   → 判定栈（Nuxt / Next / Webflow / 自研）

2. 抓壳
   curl -sSL <target> -o index.html --compressed
   → 若返回乱码，试 brotli.decompress()
   → 探测 .map：curl -sSI <target>/<main>.js.map

3. 枚举资源
   grep -oE '/(_nuxt|_next|static|js|css)/[A-Za-z0-9._-]+' index.html
   → 得到资源清单

4. 破防（按需）
   ├─ XOR 混淆 → CDP 执行解密器读 DOM
   ├─ Cloudflare → 走代理 + 完整浏览器头 + brotli 解压
   └─ 防盗链   → CDP Network.getResponseBody

5. 铺文件
   每个文件铺到所有可能的路径前缀
   → _raw/d.js → local/static/js/d.js + local/js/d.js

6. 起服务
   每站独立端口，root = local/

7. 补全循环
   find_missing.js → 抓 404 → 回原站下载 → 铺路径
   → 重复到 404 清零

7.5 反向补全（更准）
   REPLICA_PROXY=1 python serve_all.py     ← 代理模式，本地缺的去原站取并记账
   node complete-loop.mjs --report-only    ← 读日志，得到权威缺口清单

8. 验收
   截图（--screenshot）+ 推进（滚轮）+ 结构（--dump-dom）
   → 三重校验
   node verify.mjs --conc=2 --sitepar=1    ← 逐条比对（骨架/词集/高度/坏图）

9. 抽组件
   从 CSS/JS 里正则出 easing / grid / color token
   → 整理成可复用片段

10. 三件收尾核查（漏了会白干）
    ├─ 字体：node font-audit.mjs       ← 字节核对，同名不同版是常态
    ├─ 死链：grep -rE 'localhost:[0-9]+|\.vercel\.app' local/
    └─ 懒加载：页面里还有多少 [data-src] 没被搬到 src
```

**十个必须记住的坑：**

1. **SPA 回退会吃掉 JSON** → 只对页面导航回退
2. **Webflow `integrity` 哈希** → 删掉
3. **死掉的 vendor 脚本返回 HTML** → 删掉，否则整站 JS 死
4. **curl `--compressed` 不解 brotli** → 手动 `brotli.decompress()`
5. **CDP 在某些环境会挂** → 用原生 `chrome --headless --screenshot`
6. **headless WebGL 不画** → 用 `--dump-dom` 验证结构
7. **预加载器推不动** → 用滚轮事件驱动
8. **字体同名不同版** → **按字节核对，不按文件名**（01 宽 10%、05 差 8 倍）
9. **懒加载的图不在 `src` 里** → 查 `data-src`，且文件可能压根没下载
10. **验收采早了** → 等骨架连续 4 次不变再采，否则拿半成品比成品
