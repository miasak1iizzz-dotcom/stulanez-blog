# Codex 与 Cursor 并行协作协议

本协议用于 Codex、Cursor 和用户在同一工作区同时推进 `stulanez.com` 时，避免文件覆盖、误暂存、Git 历史冲突和开发服务互相占用。它是本仓库的权威协作约定；`AGENTS.md` 与 `.cursor/rules/ai-collaboration.mdc` 均以此为准。

## 1. 核心原则

1. **先认领，后修改**：任何写入前，先检查工作区和现有认领。
2. **一个文件，同一时刻只有一个负责人**：文件、目录或生成输出的认领具有排他性。
3. **不明改动一律保留**：不是自己产生的改动，视为用户或另一代理的工作。
4. **只提交自己的范围**：不批量暂存，不顺手修复或格式化范围外文件。
5. **共享工作区不改写历史**：不强推，不在他人工作活跃时变基、合并、切分支或清理工作树。

## 2. 开工前检查与认领

每项会写文件的任务开始前：

1. 读取本协议。
2. 查看 `.ai-work/claims/` 中其他代理的认领文件。
3. 执行 `git status --short`，必要时再查看相关文件的 `git diff -- <path>`。
4. 从 `.ai-work/CLAIM_TEMPLATE.md` 创建自己的认领文件：
   - Codex：`.ai-work/claims/codex-<task>.md`
   - Cursor：`.ai-work/claims/cursor-<task>.md`
5. 填写准确的文件清单、可能产生的生成文件和占用端口，然后才能修改。
6. 执行 `pnpm exec tsx scripts/check-agent-claims.ts --claim <认领文件名去掉.md>`；只有退出码为 0 才能开始写入。

认领文件只用于本机协调，已被 Git 忽略。任务名使用简短的小写英文和连字符，例如 `codex-home-hero.md`。同一代理的不同任务也必须使用不同文件。

### 认领粒度

- 优先认领具体文件，如 `src/components/HomeHero.astro`。
- 只有确实需要跨目录重构时才认领目录，如 `src/components/search/**`。
- 目录认领覆盖其所有子文件；与现有文件认领有交集即视为冲突。
- 下列共享文件必须单独、排他认领：`package.json`、`pnpm-lock.yaml`、`astro.config.mjs`、`src/config/**`、全局布局、全局样式、路由入口、生成脚本及其输出、协作协议文件。
- `src/data/agent-board/` 下的六个共享状态文件是例外：不得放入长期任务认领，统一走“Agent 看板中心”章节的原子短锁。
- 如果认领范围重叠，后到者不得编辑；应拆分任务到不重叠文件，或让用户决定优先级。

## 3. 工作期间的边界

- 只修改认领文件。发现必须扩大范围时，先更新自己的认领并再次检查冲突。
- 不移动、删除、恢复或重命名他人认领的文件。
- 不使用会扫过整个源码树的写命令。另一认领活跃时，禁止运行 `pnpm format` 和带自动修复的全仓库 `pnpm lint`；改为只对自己认领的文件运行 Biome。
- `pnpm check`、`pnpm type-check` 和 `pnpm build` 可用于验证，但如果命令会刷新已跟踪的生成文件，必须先认领这些输出，并在运行后检查 `git status --short`。
- 不覆盖未知改动来“修复”测试；先确认失败是否来自自己的文件。
- 开发服务器避免抢占端口：首个任务可用 `4321`，其他任务在认领文件中登记 `4322`、`4323` 等独立端口。

## 4. Git 安全边界

共享工作区中禁止：

- `git add .`、`git add -A`、`git commit -a`
- `git reset --hard`、`git clean`、`git stash`
- 对非本人文件执行 `git restore` 或删除操作
- 另一认领活跃时执行 `git pull`、`git rebase`、`git merge`、`git switch` 或 `git checkout`
- 强制推送或修改另一代理的提交

提交时应逐项暂存，例如 `git add -- <owned-path-1> <owned-path-2>`，随后执行 `git diff --cached --name-only`，确认列表只包含本人认领的文件。提交信息使用 Conventional Commits。

如果推送因远端已有新提交而失败，不在脏的共享工作区内强行拉取或变基；保留提交并向用户报告，待双方释放认领后再同步。

## 5. 完成、交接与释放

完成任务时按顺序执行：

1. 对照认领清单检查 `git diff --name-only` 和 `git status --short`。
2. 运行与改动相称的验证，并记录成功、失败及既有问题。
3. 只提交或交接本人认领的文件；说明修改内容、验证结果和遗留事项。
4. 确认没有后台写进程仍会改文件，再删除**自己的**认领文件。

**收工必须自行上线（老板 2026-09-07 明确，所有代理强制）：** 每干完一个功能（或对站点/资产/协议的任何改动），负责的 AI 必须自己 `git push origin main` 推上线，让 Vercel 自动重新部署——改动不许留在本地工作区「等老板」或「等别人推」。这是硬规矩，不是可选项。推前按 §4 逐项暂存、只推本人认领范围；远端有新提交冲突时按 §4 处理，不强行变基、不推无关文件。

如果任务暂停或交给另一代理，不要直接删除认领。先把 `Status` 改为 `handoff`，写明已完成内容、待办、验证结果和接手所需文件；接手方确认后再完成所有权转移。

## 6. 冲突与异常处理

- 发现对方正在修改自己认领的文件：立即停止该文件的写入，保留现场并报告用户，不自动选择任何一方版本。
- 发现未认领的既有改动：不得假定它们可覆盖、格式化或提交；先避开，确实阻塞时再询问用户。
- 认领文件明显陈旧：不得自行删除。根据其中的时间和交接信息联系用户确认；只有原负责人或用户可以释放。
- 构建或格式化意外改动范围外文件：不继续暂存，记录文件列表并让原负责人或用户处理。

## 7. 推荐的任务拆分

并行工作尽量按低耦合边界拆分，例如：内容与文案、单个页面组件、独立样式模块、图片资源处理、配置或构建流程。涉及 `package.json`、锁文件、全局布局、全局样式和站点配置的任务尽量串行；若改动规模较大，优先为代理建立独立 Git worktree，而不是共享同一工作树。


## 8. Token 成本纪律（2026-09-07 新增，所有代理强制执行）

老板按 token 付费，且坚持**每任务新开对话**。会话越长，每一步都在为全部历史重复付费——省 token 的第一原则是「少读、少试错、少绕路」。以下为硬规则：

**开工前：**

1. 新对话只读必读项：本协议、`CURRENT-STATE.md`、当前任务直接涉及的文件。禁止全库浏览和「先看看」式阅读。
2. 大文件（`tasks.json`、`inbox.json`、大 JSON 产物）只精读所需片段：先 grep/脚本定位，再按行号区间读；改哪条读哪条，改完不重读。
3. 需要看图的任务（联络表目检、截图验收、封面挑选）：第一步先用一张小图 Read 验证视觉通道（见经验库 E-021）。本环境若无视觉，直接放弃看图，只做记录/对账类收尾，判图留给有视觉的会话；**绝不加载 browser-use / computer-use 等控制技能**——其说明书本身就上万 token，且对看图毫无帮助。
4. 大批量目检、全库扫描等天然高消耗的活，开工前先向老板报预估成本量级，点头再跑。

**干活中：**

5. 复杂脚本写成 `.ai-work/` 下的临时 `.mjs` 文件执行；禁用 `node -e` 长单行（引号转义翻车即白烧错误堆栈）。
6. 命令输出只取摘要和聚合计数；禁止把全库清单、整份 JSON dump 进对话。
7. 已写入的文件不重读验证（Edit 成功即生效）；页面验证用状态码/关键词 grep，不整页拉回。
8. 无依赖的多个调用并行发出，减少轮次。

**收工：**照常三件套+短锁；`git diff --stat` 足矣，不贴全量 diff；给老板的汇报只写结论和数字，不复述文件内容。


## Agent 看板中心（2026-09-04 v2 全面重做）

看板服务于**老板本人**（非开发者，用大白话交流），渲染于 `/lab/agent-board/`（noindex 内部面板）。设计定论（用户拍板，勿回退）：砍掉信箱/AI笔记/新手指南/已完成墙的渲染；所有汇报大白话分段；AI 提交前必须代入老板视角自查；给方向性建议、不搞二选一；老板的反馈在板内写好一键复制。

### 文件分工

面向用户（看板渲染，必须维护）：

- `tasks.json` 任务状态机：backlog → doing → blocked/review → done；**领任务/完成/阻塞必须即时更新**
- `inbox.json` 「等你过目」卷宗：只有老板能推进的事（验收/拍板/要资源/跟进）写这里。每条含 `pages` 翻页汇报，**必含一页「我替你先验了一遍」（自查）和一页「我的建议」（方向性，非选项）**；老板处理完置 `resolved`。琐碎选择自行决策，不进队列
- `agents.json` 代理注册表：新代理入册 = 加一条（id/name/vendor/model/port/color/role/plain/status/currentTask/summaries）

AI 内部（**不再上墙渲染，仍要维护**）：

- `mail.json` 点对点信箱：交接/提问/通报写这里，处理完标 done
- `CURRENT-STATE.md` 全局现状（<200 行）：**任何代理开新对话必读；收工时更新**
- `experience.json` 经验库：**开工前先查，收工后写回新经验**

已删除（勿再写入）：`decisions.json`（并入 `inbox.json`）、`board-enrichments.json`（大白话与封面已内联进 `tasks.json`）。

### 大白话写作规范（plain / statusLine / nextStep / story / inbox pages 通用）

写给完全不懂技术的老板，不是写给另一个 AI：

1. 禁术语：不写 manifest、hash、WAL、regression、noindex 这类词；必须提概念时用生活类比（「指纹查重」而不是「全池 hash」）。
2. 分段短句：`story` 每段 ≤ 3 行，一段一个意思；`inbox` 每页 ≤ 3 段。
3. 数字具体：「判了 1,175 张、330 张进隔离区」而不是「推进了一大批」。
4. 进度诚实：`progress` 估不准就填 `null`，不要编百分比。
5. 代入自查：凡是请老板过目的产出，先自己用老板的视角验收一遍（假如这是我的私藏/我的网站，我满意吗），把结论写进汇报；拿不准的点明说，不要藏着。
6. 建议给方向：写「我倾向 X，因为…；你也可以 Y」，不搞「选项 A / 选项 B 二选一」。

### 收工三步（每段工作结束必做）

1. 更新 `tasks.json`：状态、`statusLine`（做到哪了）、`nextStep`（大白话下一步）。
2. 需要老板处理的事写进/清掉 `inbox.json`。
3. 更新 `CURRENT-STATE.md`；有新经验写 `experience.json`。

> **任务报告（老板 2026-09-07 明确，所有 AI 强制）：** 每干完一个任务（或一个可汇报的阶段），负责的 AI 必须往**自己的**报告文件 `src/data/agent-board/reports/<agentId>.json` 追加一条 `{ taskRef, at, text }`——写明干到哪、结果如何、留了什么。这是「干活留档」，写给老板和接手方看，不是可选项；`reports/` 每 AI 只写自己的文件，互不冲突（不需短锁）。空间页 `/lab/agent-board/<agent>/` 会展示这些报告。

> **新对话怎么读（省 token 铁律）：** 新对话**只读「一屏」**——`CURRENT-STATE.md`（全局现状，<200 行）＋ 被派发的那条任务的正文（`tasks.json`/`inbox.json` 对应记录）＋ 负责该任务的 AI 的空间报告（`reports/<agentId>.json`）。**禁止**把 `tasks.json` 全部任务、历史报告、`mail.json`、`experience.json` 整库吸入；需要细节时按任务号/标签精读对应记录，用 grep/脚本定位，不准全库扫描。

### 共享状态写入锁

`agents.json`、`tasks.json`、`inbox.json`、`mail.json`、`experience.json`、`CURRENT-STATE.md` 是所有代理都会更新的共享状态，**禁止写进长期任务 claim**。写入时使用短临界区：

1. `node scripts/agent-board-lock.mjs acquire <owner> "<task>"`，原子获取 `.ai-work/claims/.board-write.lock.json`。
2. 只改本次对应记录；修改前重新读取目标文件，修改后校验 JSON/Markdown 与 `git diff`。
3. `node scripts/agent-board-lock.mjs release <owner>` 立即释放。失败或暂停时也要释放；锁属于其他代理时不得删除，陈旧锁由原 owner 或用户裁决。

代理空间页（`/lab/agent-board/<agent>/`）展示各代理的活跃认领，供老板查看「谁在改哪些文件」。`pnpm exec tsx scripts/check-agent-claims.ts` 在终端执行同一套检查，并以非零退出码阻止开工。

规则：普通源码写入照常走认领卡与 Git 纪律；共享看板状态改走短锁；`.ai-work/` 与 `_kp-meta/` 仍为临时区不提交。大规模文件操作前退出 Serpent。
