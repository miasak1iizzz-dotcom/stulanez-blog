# 协议、记忆与工作记录维护

## 分层而非堆叠

- AGENTS.md：所有任务的少量底线和路由。CLAUDE.md / Cursor 常驻规则只链接入口，不复制整套规则。
- docs/ai 专题：当前有效的长期准则；按任务/路径触发。新拍板写到对应专题，标日期与来源。
- CURRENT-STATE.md：短入口和当前状态（<200行），不能变长篇工作史；只定位当前任务相关段落。
- tasks/inbox/desires：各自状态与用户决定的原始记录；reports：本人阶段事实；experience：可复用故障教训，均按 ID/关键词取相关项。
- docs/*SUMMARY、旧 briefing、.ai-work 历史规格/认领：[HISTORY.md](HISTORY.md) 按主题追溯。旧“必读”“马上执行”只代表当时，不自动生效。

## 权威与冲突

1. 系统/开发约束与用户本次明确指令照常优先；仓库内部以用户最新明确决定为准。
2. 长期规则只在一个专题维护。新决定改变旧规则时标“替代什么、为什么、何时、证据在哪里”，并改入口，不让两份都自称权威。
3. 任务状态和 owner 看当前条目；具体字段/代码行为看源码；历史数字、验证、角色分工不能当现状。冲突未解决就明确记录，不能编造统一结论。
4. 欲望、产品意向、建议与已授权任务严格分开。协议整理不能把聊天中所有点子偷偷变成正式任务。

## 后续怎么写

- 新规则先判断主题；补对应专题和来源即可。新功能没有入口时才加 INDEX 路由，不扩大常驻必读。
- 具体子目录放极短 AGENTS 入口；Cursor 用 alwaysApply=false 的路径规则。父入口覆盖跨领域任务，文件规则不能替代语义判断。
- 修改 Tab 的复制指令时带该 Tab 协议链接，防止 AI 只看到一个卡片忘记上文。不要批改未认领组件来补文案。
- 报告只留本阶段结果/验证/遗留/入口，不重复抄全部协议。历史原文保留，不能靠删证据“消除冲突”。
- 每次交付检查：入口可达、链接存在、当前规则有来源、旧文档不再要求全读；模拟实际任务只读相关链路。
- 新会话不全扫 memory/experience。需要完整资料审计才另定范围和成本；外部账户事实不通过翻旧日志猜。
